# Work item B1: Intended change: Meridian raymarch reaches the terrain at every canvas size

Depends on: G1
Parallel-safe with: B2, B3, E2, K3

## Goal
Stop Meridian going partial above about 300 px and blank above about 750 px, while keeping its calibrated 256 px output identical.

## Files
- packages/operators/src/sop/heightfield/surface-raymarch.ts
- packages/operators/src/sop/heightfield/surface-raymarch.golden.test.ts
- packages/operators/src/sop/heightfield/__snapshots__/surface-raymarch.golden.test.ts.snap
- packages/patches/src/meridian.*.golden.test.ts
- packages/patches/src/__snapshots__/meridian.*

## Steps
- In surface-raymarch, compute a per-ray exit distance t_exit: where the ray drops below y = -amplitude, the lowest reachable surface, plus a margin. Use marchLimit = max(params.maxDist, max over rays of t_exit). Raise the step budget proportionally (maxSteps × marchLimit / maxDist).
- Normalise depth as t / marchLimit. At 256 px marchLimit should equal 700, which leaves depth unchanged; check this.
- Add tests: hits/seeds ≥ 0.9 at 400, 800 and 1600 px, and 256 px node and render digests unchanged.
- Re-pin Meridian goldens for sizes above 256 in one commit labelled 'intended output change: meridian raymarch reach'. The commit message lists the per-size hit ratios before and after.

## Verification
Each of these must hold:
- `bun test packages/patches packages/operators` exits 0.
- `git diff HEAD~1 -- packages/patches/src/__snapshots__/meridian.render.golden.test.ts.snap` changes no 256x256 entry.
- The hit-ratio test passes at 400, 800 and 1600 px.

## Risk
Medium. This changes how Meridian looks in the gallery: more marks, and colour by depth spread over a larger range. That is the intended fix of a blank or partial image. The deeper unit problem (amplitude 80 with a scene-relative camera) is deferred.
