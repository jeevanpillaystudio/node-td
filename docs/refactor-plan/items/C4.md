# Work item C4: Stop operators and hosts from mutating cached outputs

Depends on: S2, S3
Parallel-safe with: C1, C2, C3

## Goal
Treat cook outputs as immutable, so re-composites and re-blits take the same code path whatever happened before.

## Files
- packages/engine/src/operators/rop/composite.ts
- packages/engine/src/render/canvas-2d.ts
- packages/engine/src/operators/rop/stroke-renderer.ts
- packages/engine/test/immutability.test.ts

## Steps
- composite.ts: remove `layers[i]._canvas = undefined` (lines 66 and 73). Returning the single input object at line 50 stays, which is fine now that outputs are immutable.
- render/canvas-2d.ts blitBuffer2D: remove `buffer._canvas = undefined` (lines 136-139).
- Update the stroke-renderer.ts:343-353 comment to say canvases are released when the host clears the cache.
- Add packages/engine/test/immutability.test.ts:
- Clone the registry, wrapping each evaluate so it digests its outputs on return.
- Cook each gallery patch, then call blitBuffer2D on the terminal into a RecordingCanvas, with a stub global ImageData.
- Re-digest every cached output and assert it is unchanged.
- A no-op second cook must also return the same objects.

## Verification
Each of these must hold:
- `bun test packages/engine` exits 0, including immutability.test.ts.
- Snapshots are unchanged (`git status --porcelain -- ':(glob)**/__snapshots__/**'` empty).
- `grep -rn '_canvas = undefined' packages` prints nothing.

## Risk
Low or medium. Frame still clears its cache after every draw, so its memory profile is unchanged. EditorPreview, which never clears, now keeps 3-4 layer canvases per patch at 4× preview size, roughly 20-25 MB. That is acceptable until the deferred retention policy exists.
