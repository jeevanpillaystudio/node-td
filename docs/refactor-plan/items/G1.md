# Work item G1: Geometry attribute pass-through and per-vertex colour on the geometry (retire the Palette sideband)

Depends on: K6a, K6b
Parallel-safe with: K3

## Goal
SOPs keep the attributes they do not touch. Per-vertex colour travels on the geometry as `colors`, alongside `normals`, instead of as a Palette whose count happens to equal vertexCount. Render output is identical.

## Steps
- Move the geometry helpers (pointsGeometry, pathsGeometry, geometryToPaths, vertexAt) from types.ts to kernel/src/geometry.ts. Add withPositions(geo, positions, dim), which carries attributes, normals, colors, indices and stripOffsets; filterVertices(geo, keep), which splits strips and carries attributes; forEachStrip; pathsGeometry3; and Geometry.colors?: Float32Array (rgb per vertex).
- Use these helpers in surface-lift, project-3d, geometric-normal, visibility-cull and merge so they pass attributes, normals and colors through.
- Move diffuse-shade with git mv to sop/diffuse-shade.ts (category sop). It takes geo3 plus a palette and outputs geo3 with `colors`.
- stroke-renderer reads geometry.colors for per-vertex and per-strip colour. Delete the `palette.count === vertexCount` checks at the former lines 176 and 245.
- Rewire subscapes to cull→shade→proj→render.geometry. render.palette is either unwired or wired to the single-colour palette, whichever reproduces the exact command stream.
- Remove MAT from OperatorCategory and from the taxonomy test exception.
- Delete surface-raymarch's unread normalX/normalY/normalZ and worldY attributes.
- Re-pin node and op goldens in one commit labelled 'test: re-pin node digests after attribute pass-through (render unchanged)'.
